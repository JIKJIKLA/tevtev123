# Nivet League 10.6.0 — Drive verification

This movement-only release responds to the report that10.5.0 still loses ordinary control. Visuals, ball tuning, effects and unrelated features are frozen. Source correctness, recorded controller trajectories and native keyboard handling are separate acceptance requirements. A passing automated test or eventual upright pose is not treated as proof of satisfying handling.

## Reproduced causes and bounded changes

Two failures have direct before/after evidence:

1. An already-held digital driving key became an aerial pitch command immediately after a tap jump or support departure. In the native10.5.0 diagnostic-camera run, jump tick55 started local pitch,32ticks later angular velocity reached−3.311rad/s, tick116 became inverted at the5.5rad/s air cap, and tick160 contacted the roof/hull. Steering subsequently acted on that inverted body. The isolated held-forward tap-jump profile failed to regain stable support within2.5s. The current source remembers only an already-held, wheel-supported coupled driving direction. Release/repress restores real aerial pitch; independent controller/touch axes, yaw, roll and raw dodge/cancellation commands retain their meaning. The same controlled tap-jump profile now regains real supported control at1.075s.
2. The center's1m/s outward-speed cutoff rejected four actual loaded tyres during a fast rounded wall return. At zero-based tick23 in10.5.0, alignment was0.999590 and the minimum tyre gap was0.200mm, yet center outward speed2.065704m/s selected AIR. The support decision now also recognizes a sampled tyre within the existing15mm rest gap, while retaining jump lock, real wheel count/alignment and the old speed gate for more extended suspension. Loaded four-wheel AIR samples in this fixture decrease from three to zero; actual geometric departures remain airborne with zero tire traction.

These are measured Nivet failures. Their complete causes and limits are recorded in [keyboard/steering evidence](STEERING-REPAIR.md), [contact continuity](CONTACT-CONTINUITY.md), [steering trajectories](measurements/steering-response.json) and [contact trajectories](measurements/contact-continuity.json). The exact source of each old linear projection is not isolated; a duplicated angular transfer was not reproduced. The sixfold stable→partial→air→partial→stable audit preserves yaw to floating-point precision across all three bodies on floor and wall. Existing angular conversions, ordinary ground steering/grip, hull constraints, deliberate dodge cancellation and bounded recovery mechanisms therefore remain. No additional upright target, camera smoothing layer or ground force in genuine flight is introduced.

## Shared-state and prediction review

Only one new persistent car state was added relative to10.5.0: `carriedPitch` in `{−1,0,1}`. It is initialized/reset and included in `DRIVER_SCALARS` for authority reconstruction. New input metadata `coupledPitch` is an exact integer0/1 flag; it travels with input histories and remote controls. The server rejects strings, booleans, fractional/out-of-range values and ignores attempts to submit authoritative state through controls. Omitting the flag preserves independent-axis behavior. Source wire4 and gameplay protocol7 prevent mixed handling versions.

`tests/handling-prediction.test.cjs` extends the focused keyboard checks with18actual human-mapper scenarios: all three body profiles,1v1/2v2/3v3 rosters, and Soccar/Heatseeker. Each begins driving with W, taps jump on tick13, captures an airborne carried-input snapshot on tick24, releases on tick60 and presses W again on tick61. Even this single neutral tick clears inherited input and the new airborne press produces real pitch. Authority and prediction car position/quaternion/linear and angular velocities/supported yaw/carried state and ball position/velocity/spin match on every tick through84. After deliberately corrupting client carried state, rotation, angular velocity and position, restoring the old carried snapshot and replaying all60pending inputs still produces exact final state with carry cleared. Profile bodies are applied through the same multiplayer seats channel as the game; remote seats are placed away from the local trajectory so authority-only remote-car collisions are not falsely included in a local-prediction equality claim.

The additional reconstruction check accepts only `{−1,0,1}`, retains the previous value on malformed state, clears it on reset, and confirms independent aerial pitch remains active. Steering work's two complementary tests cover uninterrupted carried intent and independent airborne axes through reconciliation. Existing prediction tests retain delayed/jittered/discarded downstream snapshots, adverse synthetic uplink, impact recoil and actual one/two-wheel reconstruction.
